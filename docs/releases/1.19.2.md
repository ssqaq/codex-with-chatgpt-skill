# 1.19.2：修复评审卡住，按30秒以内检查网页

本版重点是让评审继续得更顺，并把网页检查标准按用户确认改成30秒以内。

默认还是 **DeepSeek**，保持“深度思考”和“智能搜索”开启。你说“用 GPT/ChatGPT”才切换。

1. **修复“恢复次数已用完”误报。**上一项评审用过一次恢复，不会再拖累下一项；同一任务仍限制恢复次数，避免一直重连。
2. **原标签关了，先找回原对话。**你已允许、原对话确实不存在时，会新建并带上已确认的方案摘要继续。登录失效、加载慢、消息发没发出去不清楚时，会先说明卡点。
3. **清理互相矛盾的旧说明。**两份配套 Skill 都使用当前浏览器恢复规则，不再强制寻找宿主没有提供的旧接口。
4. **补测了真实执行。**做完两组：一组4轮方案、一组3轮方案；两组都在共识后实际改独立项目，跑23项测试、检查页面，再让 DeepSeek 单独复核结果。本次调整后核心402项测试、类型检查和构建通过。
5. **按30秒以内看一次网页。**发送后马上检查，后续从上次实际检查时间计算30秒截止；工具运行和保存记录也占用这段时间，到期立即查，看到完整回复立即往下做。每满一分钟仍会显示轮数和等待时长。
6. **速度如实说。**第二组三轮分别约1分49秒、1分32秒、1分42秒，三轮方案共约5分8秒。30秒是检查间隔目标，不是保证网页30秒内回答。受 Codex 和浏览器调度影响，不能保证严格实时；实际超过30秒会留下记录，旧复测的超时也不会改成通过。

7. **修复单次评审启动被拦住。**补齐旧配套脚本遗漏的智能搜索和当前模型配置；单次、多轮两种入口均补测通过。最后一次真实单次复核的检查间隔为24.560秒，回复正确回显并通过核对。

原标签关闭后找回同一对话做了真实测试；“原对话确实不存在后新建”的保护分支只做了脚本模拟，没有删除真实对话制造测试。

想用，直接说：

> 使用 Codex with ChatGPT，让 DeepSeek 多轮评审这个问题。每轮显示轮次，双方确认方案后自动修改、测试和检查页面，最后复核结果。原对话确实找不回时，允许新建并带上已确认摘要继续。

完整时间和范围见[复测记录](https://github.com/ssqaq/codex-with-chatgpt-skill/blob/master/docs/verification/1.19.2.md)。旧任务重新读取更新后的 Skill 就能按新规则继续，历史消息不会改写。
