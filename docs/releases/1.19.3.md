# 1.19.3：评审恢复不卡在一次，回复及时保存

1. **同一个任务可以多次恢复**：恢复成功后又断开，可以继续找回原对话；不会再因为前面恢复过一次就把整个任务卡住。同一次故障失败后会说明卡点，不无限重连。
2. **关闭的标签可以重新找回**：先核对原对话、唯一标签和发送回执，找回后继续原轮次。消息发没发成功还不清楚时，先核对，不重复发一遍。
3. **读到回复尽快往下走**：提供一次调用中连续检查的读取脚本，完整回复到达就返回；先保存回复证据，再分析建议，减少证据放过期后重读的情况。
4. **读取中途出错不丢记录**：保留已成功读取的真实时间和内容；未写完的任务标识继续等，读到其他轮次立即停下来核对。
5. **简单问题可以少说一点**：第一轮也遵循你要求的更短回复长度。指定专项还没做完时，先记本轮通过，全部核对完才执行。
6. **重新跑完真实流程**：修复后新跑3轮方案评审，达成共识后实际改独立项目、跑33项测试、检查页面，再做一次最终复核。核心412项测试通过。
