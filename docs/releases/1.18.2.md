# 1.18.2：多轮评审遇到限流不会再卡死

1. 如果 DeepSeek、Codex 服务或浏览器返回“429 / 请求太多”，当前轮次会明确显示为“已暂停”。
2. 会保存当前轮次、限流次数和（服务提供时的）恢复时间，不会从第 1 轮重来。
3. 暂停期间不会重复发同一条消息，不会重复创建会话，也不会修改文件。
4. 到恢复时间后，只有显式执行一次恢复检查才会继续；如果仍被限流，就再次暂停。
5. 本地只保存固定的限流说明，不保存服务原始返回内容，避免令牌和账号信息落盘。

本版同时保留 1.18.1 的自动接力修复：共识完成后，如果原任务只能出方案，会在同一工作区接到普通执行任务继续修改、测试和复核。
