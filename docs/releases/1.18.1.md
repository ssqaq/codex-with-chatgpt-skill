# 1.18.1：评审完成后不再停在方案页

这一版集中修复三个会让用户误以为“卡死”的问题。

1. 进入下一轮时，如果调用方漏传了“页面只有一个匹配标签”，系统只会在任务、标签、浏览器编号和旧的页面证据完全一致时自动补上；对不上就拒绝，不会串到别的会话。
2. 一轮完成后释放浏览器使用权时，可以省略已经由当前使用权记录确认过的页面来源；如果传了错误来源，仍然会拒绝。
3. 多轮评审达成共识后，如果当前 Codex 任务只能出方案，Skill 会在同一个工作区建立正常执行任务，把共识带过去，直接改代码、跑测试和复核。用户不需要再发一次“继续”，也不会重新做一遍评审。

你看到的流程会变成：

```text
多轮评审达成共识
→ 当前任务能改文件：马上开始修改
→ 当前任务只能出方案：自动建立正常执行任务
→ 新任务带着原共识继续修改、测试和复核
```

这次还增加了反向检查：错误任务、错误标签、错误浏览器编号、错误页面来源都不能借“自动补值”接管其他会话。

仍然保持原规则：没有真实网页回执和双方共识时不能修改；测试、代码复核和需要的页面检查没有通过时不能说完成或同步。
