# 1.19.7：修好监控期间发现的三个问题

这次监控真实多轮评审时抓到三个问题，一起修完了：

1. **释放浏览器锁不再误报**：以前只想“释放/续租”自己的浏览器锁时，如果不重复填一遍浏览器身份，会被误报成“身份不一致”，看着像口令错了。现在只填锁的口令和序号就能安全释放/续租，口令或序号不对照样拒绝，缺口令也给出清楚的原因。
2. **本地进度面板不再和真实评审分叉**：有时页面已经跑到第 3 轮并达成共识，本地面板却还停在一个已经取消的旧任务上，一直显示“暂停”。现在会自动指出真正在跑的评审任务号，并给出对齐命令；你也可以显式执行对齐。对齐只做一件事：把面板指到那个已经核验过的任务，并把旧的共识、回复、回执和执行许可全部收回，必须重新走一遍核对门槛，绝不会偷偷放行改文件。
3. **失败原因不再只有一句笼统提示**：以前配套脚本失败只显示“某阶段失败”，看不出到底卡在哪。现在会把脚本自己写的中文原因原样带出来（例如“没有有效浏览器 lease。”），但仍然过滤路径、凭据和异常细节，不会把私密内容回显给你。

本机复核结果：

- 27 个测试文件、504 项测试全部通过（比上一版多 10 项，专门覆盖这三个修复）。
- 类型检查通过；构建通过。
- 两份 DeepSeek Skill 已同步安装并校验为 1.19.7。
- 新增回归覆盖：最小参数释放/续租、错口令拒绝、缺口令文案、错 runtime 拒绝、面板漂移识别、按绑定对齐、越权任务号拒绝、审计风险拒绝。

安全边界没有放松：对齐不改业务文件、不发消息；共识、回执、回复和执行许可一律作废重算；有未确认发送或审计风险时只暂停不对齐。
